## 1. Executive Summary

This optimization work is grounded in a close reading of the ALL(*) paper by Parr et al. (*Adaptive LL(\*) Parsing: The Power of Dynamic Analysis*, OOPSLA 2014). Three domain experts, specializing respectively in **ATN/DFA/HPPC/concurrency**, **character and token streams / JIT / safety**, and **tool code generation / ST4 / static analysis**, collaborated on the design and the optimizations and then performed a strict review. Following the engineering methodology of “**Arthas flame-graph localization → precise optimization → same-host cross-validation → never regress**”, we completed **three iterative optimization rounds**.

On the working tree after the final review fixes, we ran a **four-way same-host crossover with rotated trial order** (`Baseline 84f5b5fe` vs `Round 1` vs `Round 2` vs `Round 3 Final`; three trials per scenario, each executed in a rotated order) and obtained the following rigorously verified results:

1. **Strictly monotonic improvement in all 11 scenarios across all three rounds (33/33 wins):**
   - **Round 1 vs Baseline:** **11/11 improved**, geometric-mean speedup **1.390× (+39.0%)**
   - **Round 2 vs Round 1:** **11/11 improved**, a further **1.281× (+28.1%)** on top of Round 1
   - **Round 3 Final vs Round 2:** **11/11 improved**, a further **1.069× (+6.9%)** on top of Round 2
   - **Cumulative speedup (Round 3 Final vs Baseline):** geometric-mean speedup of **1.904× (+90.4%)** across the 11 serial/parallel scenarios; of these, **parallel lexing reached 2.80× (+180.5%)**, **serial lexing 2.62× (+161.9%)**, **parallel parse-tree construction 1.89× (+89.1%)**, **serial full-context LL(\*) 1.83× (+83.3%)**, **parallel cold-start DFA construction 1.64× (+64.2%)**, and **serial/parallel SLL parsing 1.57× / 1.55×**.
2. **Substantial improvements in the quality and bytecode size of the generated `GroovyLexer` / `GroovyParser`:**
   - Total method bytecode in `GroovyParser` fell from **65,081 B to 49,882 B (−23.4%)**; the number of oversized methods above the HotSpot C2 inlining threshold (`FreqInlineSize = 325 B`) dropped sharply from **48 to 25 (−47.9%)**; `_adaptivePredict` call sites fell from **326 to 186 (−42.9%)**; `switch` statements fell from **166 to 67 (−59.6%)**.
   - The total number of methods in `GroovyLexer` was reduced from **84 to 49 (−41.7%)**, and total method bytecode from **7,388 B to 6,246 B (−15.5%)**, completely eliminating 35 second-level dispatch helper methods in favor of a flat O(1) `tableswitch`.
3. **100% semantic equivalence and zero API breakage:**
   - On 70 real Apache Groovy source files (1,618,957 bytes / 1.544 MiB, 177,906 tokens, 650,437 ParseTree nodes, 0 syntax errors), the SHA-256 checksums of the complete token streams and parse trees are **100% bit-identical** to the baseline: `6ecb3e18b07718d986809c4895fac718baa4746c5c4e527e26cbe789e31c3c17`.
   - **Zero HPPC exposure:** both the `TestHppcApiBoundary` reflective scan and the Maven `verify-shaded-hppc` check confirm that HPPC types appear in **0** `public` or `protected` API signatures.
   - **High-coverage quality assurance:** three new in-depth unit-test suites were added. Combined JaCoCo line coverage of modified and newly added code reached **96.68%** (`runtime/Java` **96.96%**, `tool` **94.01%**). All of `runtime/Java` (1,220/1,220), `tool` (all 1,616 non-AWT tests), `antlr4-annotations`, `antlr4-maven-plugin`, `perf-testsuite`, and the Javadoc build passed.

### 4.2 Core Optimizations and Design Rationale for the Three Rounds

#### Round 1: Eliminate repeated ATN closure on lexer predicate edges and de-virtualize the infrastructure (geomean +39.0%)
1. **Lock-free lexer predicate-edge decision tree (`LexerPredEdgeTable`):** In the Groovy lexer, `/` (division vs. regex literal) and `'`/`"` (quotes vs. nested GStrings) carry semantic predicates. On every predicate edge, the baseline abandoned the DFA and fell back to `LexerATNSimulator.execATN` to redo a full ATN closure (25.4% of CPU). Round 1 introduced a per-mode `LexerPredEdgeTable` (caching a lightweight `PredNode` decision tree keyed by `stateNumber × ASCII[0..127]`, with COW + lock-free reads via `AtomicReferenceArray`). On the hot path it evaluates the predicate and jumps to the target `DFAState` directly, completely eliminating warm-state ATN fallback.
2. **Specialized `CodePointCharStream` lexer fast loop (`execATNFastCodePoint`) and `ClassValue` subclass eligibility gating (`FAST_EXEC_ELIGIBLE`):** When the critical `LexerATNSimulator` hook methods have not been overridden, the implementation reads the input stream's underlying array and the cached `asciiEdges` directly (COW publication guarantees JMM visibility across platforms), avoiding a virtual call and `mark`/`release` per character.
3. **De-virtualization of hot-path streams, tokens, and the parser:** direct `fromString` construction of `CodePointCharStream` and a 64-bit overflow-safe `getText(Interval)`; `LexerActionExecutor` precomputes `hasPositionDependentAction` and a single-built-in-action execution path `executeBuiltIn`; `Recognizer` error listeners replace `synchronized (this)` with a lock-free CAS array; read-only `IntervalSet`s build a `long[] fastBits` for O(1) `contains(int)`; `ATN.precedenceLL1` caches left-recursive precedence decisions in a dense array.

#### Round 2: Eliminate heap allocation, G1 write barriers, and `HashMap`/sorting bottlenecks (geomean +28.1% relative to R1)
1. **Chunked `TokenList` + fused frontier fetching (`BufferedTokenStream` / `CommonTokenStream`):** A fixed 1024-slot chunked array replaces `ArrayList<Token>`, completely eliminating the repeated `ArrayList.grow` copies that accounted for 6–8% of CPU when buffering tokens from large files. In `CommonTokenStream.consume()` and `ltForwardFast()`, frontier fetching and hidden-channel skipping are fused into `TokenList.appendFast`, while `clear()` still releases oversized chunks to prevent memory retention.
2. **Zero-allocation open-addressed `PredictionContextCache`:** Three monomorphic open-addressed hash tables (`ContextInternSet`, `ChildContextMap`, `JoinContextMap`; 0.5 load factor + O(size) sparse clear + automatic shrink above `MAX_RETAINED_CAPACITY`) replace the original `HashMap` plus `PredictionContextAndInt` / `IdentityCommutativePredictionContextOperands` wrapper objects, completely eliminating `HashMap.Node` and temporary-key allocation and driving **+37% to +64%** gains on `serial_parse_ll_warm` / `parallel_parse_tree_warm`.
3. **Allocation-free SLL hot path `execDFASllWarm` and zero-allocation predicate evaluation:** In the warm SLL path, writes to the `this.dfa` field are skipped (eliminating high-frequency G1 write barriers) and `SimulatorState` allocation is skipped; a single-token, predicate-free accept returns immediately; predicate accepts are evaluated with zero `BitSet` allocation via `evalSemanticContextSingle` / `evalSemanticContextUnique`.
4. **128-bit Bloom fast rejection + packed `long[]` conflict detection (`ParserATNSimulator.isConflicted`):** The vast majority of non-conflicting configuration sets are rejected directly in O(n) by a 128-bit Bloom bitmask; the remainder packs `(nonStopState, alt, index)` into a reused `long[]` for sorting (`stateNumber >= 1<<20` automatically falls back to two-array mergesort), completely eliminating `ATNConfig[]` allocation and lambda-comparator overhead.
5. **8-bit byte-stream specialized scan `execATNFast8Bit` + 32-byte compact `ATNConfig` + `EpsilonClosure.closeOneDirect`:** `passedThroughNonGreedyDecision` is moved into the `ATNConfig` base class's alignment padding (preserving a 32-byte object size under 64-bit CompressedOops and eliminating polymorphic dispatch), MurmurHash3 is hand-inlined, `equals` uses a cached-hash fast reject, and `EpsilonClosure` is expanded internally into a virtual-call-free `closeOneDirect`.

#### Round 3: Deep tool code-generation optimizations + HotSpot C2 MDO profile isolation + `-> skip` lexer fusion (geomean +6.9% relative to R2, cumulative +90.4%)
1. **ALL(*)-rigorous EBNF-exit LL(1) recovery (`AnalysisPipeline.recoverSingleAltEbnfExitLookahead`):** In the Groovy grammar, many `nls*` (newline loops) are immediately followed by a left-recursive expression or a subrule with a contextual predicate, causing the original `LL1Analyzer` to give up on encountering a predicate and fall back to `_adaptivePredict`. Following the ALL(*) paper and `EpsilonClosure` semantics, we **see through only** the invoked-rule predicates that ALL(*) necessarily drops at `depth > 0` (`PrecedencePredicateTransition` and context-dependent `PredicateTransition`), leaving context-independent predicates opaque. This fully preserves ALL(*) theoretical completeness while cutting `_adaptivePredict` call sites in `GroovyParser` from **326 to 186 (−42.9%)**!
2. **Compact single-token star loops (`_matchStar` / `_matchStarPredict`) and compact LL(1) bitmask tests:** Gated by `Target.supportsCompactSingleTokenStarLoop()` / `Target.supportsCompactLL1AltTests()` (enabled only on `JavaTarget`; third-party targets default to `false` and remain fully compatible). 176 repeated inline `setState`/`_sync`/`while`/`_match` loops and 99 redundant `switch`es are collapsed into compact calls and 64-bit bitmask tests, reducing total `GroovyParser` bytecode by **23.4%** and the number of methods above C2 `FreqInlineSize` (325 B) by **47.9%**!
3. **Two-tier zero-copy optimization for labeled alternatives (Tier 2a direct subclass construction / Tier 2b `_enterDeferred` deferred push):** On the hot path where `_parseListeners == null` and there is no user `catch`/`finally`, avoid allocating a base `RuleContext` and then `copyFrom()` into a concrete `AltContext` subclass. When listeners are present, strictly fall back to the standard ANTLR4 callback order (first `enterEveryRule(BaseContext)`, then replace with the subclass and fire `exitAlt`).
4. **Flat O(1) `action()` / `sempred()` dispatch:** Eliminates 35 second-level dispatch helper methods in `GroovyLexer` in favor of a single-level `tableswitch` dispatched directly on `actionIndex`/`predIndex`. The parameter is renamed `_ruleIndex` to avoid clashes with user members/locals. Parser predicates that refer to `_localctx` are automatically extracted into strongly typed helpers (and automatically fall back when they reference `predIndex`).
5. **HotSpot C2 MDO profile isolation (`CommonTokenStream.LT` / `BufferedTokenStream.LA`):** `-XX:+LogCompilation` evidence showed that the original `LT(int)` mixed cold `k==1` cache misses with the hot `k!=1` path in the same branch, causing C2 to inline the cold `ltCommonSlow` path into 206 generated `_match()` / `LA(1)` call sites and blow through `NodeCountInliningCutoff`! After splitting out `ltOneSlow()` / `laOneSlow()`, each larger than 35 B, cold-path inlining counts fell from **206 + 507 to 13 + 1 (−99.8%)**!
6. **In-place `-> skip` fusion (`LexerATNSimulator.execATNFast8Bit` / `execATNFastCodePoint`):** `SKIP_FUSION_ELIGIBLE` verifies that `Lexer` has not overridden `nextToken()`/`skip()` and that execution is at the normal `nextToken()` entry (standalone `sim.match()` calls keep single-token semantics). Inside the hot DFA loop, built-in `-> skip` rules (such as whitespace `WS -> skip`, which accounts for about 40% of Groovy lexer match counts) are skipped in place, avoiding a full `nextToken()` round trip and action-dispatch overhead.

### 4.3 In-Depth Debugging and Lessons from Failed Approaches (Based on Empirical `LogCompilation` Evidence)

During the Round 3 push, we encountered several subtle JIT traps that caused some local metrics to regress rather than improve. All were precisely root-caused with Arthas flame graphs and `-XX:+LogCompilation` and fully resolved:
- **Failed approach 1 (abandoned):** Inlining DFA character scanning into `Lexer.scan8Bit`/`scan16Bit` — caused the 11% of cases that take the predicate-edge fallback to trigger a double scan, and bloated `nextTokenCodePoint` to 25.8 KB of machine code, regressing `serial_lex_warm` by −9%. **Lesson:** keep `execATNFast8Bit` inside `LexerATNSimulator` and perform `resolveTargetFast` and `-> skip` fusion in place; this avoids fallback rescan and stays compact in the L1i cache.
- **Failed approach 2 (abandoned):** Pre-reading `input.LA(2)` in `execDFASllWarm` — increased bytecode size and pushed `DFAState.getTarget` out of the C2 inlining budget.
- **Failed approach 3 (abandoned):** Generating `_tryPredict` (Tier 2c) on LL(\*) rules — bloated `GroovyParser.expression(int)` to 141 KB of C2 code and triggered double predicate prediction.
- **Failed approach 4 (resolved):** Shrinking `GroovyLexer.action()` to `< 325 B`, or repeatedly inlining `lexer.action()` from `LexerActionExecutor.execute` — caused aggressive C2 inlining to hit `NodeCountInliningCutoff` and produced bimodal jitter on `parallel_lex_warm`. Keeping `GroovyLexer.action()` at **343 B** (slightly above the 325 B threshold) with a single call site completely eliminated the bimodality and delivered a stable +9.0% speedup.

## 7. Record of the Strict Review by Three Domain Experts and Full Issue Closure

After the three performance-optimization rounds, three domain experts jointly performed a line-by-line in-depth audit of all 58 changed files. The following key issues were found and **all were fixed and closed** (every fix is included in the final four-version crossover performance verification above, with additional regression unit tests):

| Review area | Severity | Issue found | Fix |
| --- | --- | --- | --- |
| ATN/DFA/concurrency (Expert #1) | **CRITICAL** | `ParserATNSimulator.execDFASllWarm` called `repeatedEof(states, null, ...)` on a non-accepting EOF edge without a null check on `contexts`, causing an NPE | Added a null guard on `contexts` in `repeatedEof` and a regression unit test |
| ATN/DFA/concurrency (Expert #1) | **CRITICAL** | `DFAState.asciiEdges` was mutated in place rather than COW, so on weak memory models (ARM64/POWER) a reader could observe a not-fully-initialized `DFAState` (a JMM race); `contextSymbols` lacked `volatile` | Changed `asciiEdges` to `prev.clone()` COW + a single `volatile` publication; added `volatile` to `contextSymbols`; cached `minEdgeIndex` as `final` |
| ATN/DFA/concurrency (Expert #1) | **CRITICAL** | Raw array rows in `LexerPredEdgeTable`, together with `ATN.modeToPredEdges` / `clearDFA()`, had concurrent-visibility hazards | Rows became `AtomicReferenceArray<PredNode>` + COW publication of `byState` + a `(asciiChar & ~0x7F) != 0` bounds check; `clearDFA()` is now lock-protected |
| ATN/DFA/concurrency (Expert #1) | **CRITICAL** | `LexerATNSimulator` `FAST_EXEC_ELIGIBLE` failed to detect overrides of `addDFAEdge`/`addDFAState`/`getReachableTarget`; `-> skip` fusion must verify that `Lexer` has not overridden `nextToken`/`skip` and that fusion is triggered only at the `nextToken()` entry | Completed the method-eligibility allowlist and added `SKIP_FUSION_ELIGIBLE` + a precise `recog._tokenStartCharIndex == startIndex` gate |
| ATN/DFA/concurrency (Expert #1) | **MAJOR** | `ATNConfigSet.mergeConfigContext` flipped `reachesIntoOuterContext` without invalidating the cached hash; `PredictionContextCache.clear()` checked shrink after the sparse clear, so large tables did not shrink; `ATNConfig.computeHashCode` did not read `hasPassedThroughNonGreedyDecision()` through the polymorphic getter | Invalidated the hash, moved the large-table shrink check before the sparse clear, called `hasPassedThroughNonGreedyDecision()`, and normalized a `null` `contextCache` to `UNCACHED` |
| Streams/lexing/safety (Expert #2) | **MAJOR** | `CodePointCharStream.getText(Interval)` could overflow 32-bit integers on extremely large integer intervals; dynamic `_input` swaps in `Lexer` actions (including `more()`) needed complete handling on edge paths; `CommonTokenStream` could hit a stale cache when `fastTokens` was truncated externally or a subclass overrode `LB`; `RuleContext.getText()` was inconsistent with `StringBuilder` when a single child's text was `null` | Extracted a 64-bit overflow-safe `computeTextLength(...)`; completed stream-swap and `emitEOF()` logic in `nextTokenCodePoint` / `finishMoreGeneric`; added precise class and bounds checks for `cachedLTMinus1` / `seek` / `ltForwardFast`; a single-child `null` now returns `"null"`; `TokenList.clear()` releases oversized chunks; `IntervalSet.buildFastBits()` gained an out-of-order defensive check; `Recognizer` listeners moved to lock-free CAS |
| Tool code generation/analysis (Expert #3) | **CRITICAL** | `Choice.extractSingleTokenMatch` used only `instanceof MatchToken`, which could incorrectly fold `.*?`/`.*`/`(~A)*` (`Wildcard`/`MatchSet` subclasses) and cause compilation failure | Changed to an exact-class test: `cur.getClass() == MatchToken.class && mt.name != null && mt.ttype > 0` |
| Tool code generation/analysis (Expert #3) | **CRITICAL** | `AnalysisPipeline.recoverSingleAltEbnfExitLookahead` seeing through context-independent predicates would break ALL(*) predicate-hoisting semantics | Strictly limited see-through to `PrecedencePredicateTransition` and context-dependent `PredicateTransition`, which ALL(*) drops at `depth > 0`, and added ALL(*) semantic-soundness unit tests |
| Tool code generation/analysis (Expert #3) | **CRITICAL** | In `Java.stg`, `_matchEOF()` writing `Token.EOF` can be shadowed by a lexer token named `Token`; the flat `action()`/`sempred()` parameter `ruleIndex` can be shadowed by a user member or local; Tier 2b must exclude rules that have `catch`/`finally` or a non-empty `preamble` | Changed to `EOF`, renamed the parameter to `_ruleIndex`, fully excluded those rules from Tier 2b and guarded `_localctx == null` in `catch`, added a Tier 2a guard `if (!(_localctx instanceof ...))`, and automatically fall back when a `_localctx` predicate refers to `predIndex` |
